Що зроблено на сайті — травень 2026

Останнє оновлення: 2026-05-28

Огляд

Виконано перший та другий етапи SEO-аудиту сайту zdorovo-dent.com.ua. Усі зміни стосуються технічної частини — вони невидимі для відвідувачів, але покращують те, як Google і інші пошукові системи сприймають та індексують сайт. Додатково виконано аварійне відновлення після автоматичного оновлення WordPress.

Що змінилося

1. Зображення завантажуються швидше

Проблема. Три плагіни одночасно застосовували JavaScript-залежне відкладене завантаження зображень. Якщо скрипт не завантажувався (повільне з'єднання, блокувальник реклами, помилка скрипта або робот пошукової системи) — зображення взагалі не з'являлися. Крім того, головне зображення на першому екрані завантажувалося з затримкою, що погіршувало показник LCP (час завантаження найбільшого елемента).

Виправлено. Замінено на нативне завантаження браузера — без скриптів, гарантовано працює в усіх умовах. Головне зображення встановлено як пріоритетне для миттєвого завантаження.

2. Прибрано зайві посилання з robots.txt

Проблема. Файл robots.txt містив посилання на новинну карту сайту (sitemap-news.xml), яка не має значення для стоматологічної клініки. Це зайве навантаження на краулерів Google.

Виправлено. Зайві посилання прибрано з robots.txt. Основна карта сайту (sitemap.xml) залишається.

3. Карта сайту більше не позначається як «не для індексації»

Проблема. Плагін All in One SEO надсилав технічний заголовок X-Robots-Tag: noindex у відповідь на запити до карти сайту. Деякі SEO-інструменти позначали це як проблему — файл виявлення для пошукових роботів не повинен бути позначений як не для індексації.

Виправлено. Заголовок прибрано з усіх відповідей карти сайту.

4. Сторінки-дублікати виключено з індексації

Проблема. Плагін галереї BEAF (блок «До / Після») створював окремі URL для кожного слайдера (/?bafg=назва). Це технічні сторінки без власного змісту — Google їх індексував і витрачав на них краулерний бюджет.

Виправлено. Такі сторінки тепер позначені для Google як «не індексувати, не переходити за посиланнями». Самі слайдери продовжують нормально працювати в режимі вбудованого віджета.

5. Прибрано мовну позначку для російської мови

Проблема. У коді кожної сторінки містилась технічна позначка hreflang="ru" — залишок від давно видаленого російського перекладу. Google отримував сигнал про існування російської версії, якої немає.

Виправлено. Позначку прибрано. Додано стандартну позначку hreflang="x-default", яка вказує, що українська версія є основною для всіх регіонів.

6. Структуровані дані: повне виправлення

Детальний опис — у документі structured-data-uk.md. Коротко:

  • Усунено дублювання карток клініки в структурованих даних (три версії → одна)
  • Виправлено код країни в адресі (Україна → UA) — раніше Google ігнорував увесь блок адреси
  • Додано адресу до організаційної картки
  • Прибрано неправильний тип сторінки (Article) з головної — тепер правильно WebPage
  • Прибрано зайвий блок SiteNavigationElement
  • Відновлено блок WebPage на всіх сторінках
  • Додано автора до записів блогу (необхідно для розширених результатів Google)
  • Виправлено навігаційні хлібні крихти: підпис «Головна», відображення поточної сторінки

7. Усунено приховане дублювання структурованих даних

Проблема. Після розгортання попередніх виправлень виявилося, що тема Astra самостійно додавала у вихідний код сторінок власну розмітку (Organization, WPHeader, WPFooter, CreativeWork). В результаті Google бачив картку клініки тричі — двічі від теми і один раз від плагіна структурованих даних. Валідатори Google сигналізували про помилку дублювання.

Виправлено. Власна розмітка теми Astra вимкнена — тепер усі структуровані дані виходять виключно з одного плагіна. Дублювань немає.

8. Фіксоване меню при прокручуванні

Запит клієнта. Шапка сайту повинна залишатися видимою при прокручуванні сторінки вниз.

Виконано. Шапка тепер зафіксована у верхній частині екрана. Реалізовано через CSS без JavaScript — не впливає на швидкість завантаження та показник CLS (зсув верстки). Коректно працює із панеллю адміністратора WordPress.

9. Банер згоди на cookies (GDPR)

Проблема. На сайті не було повідомлення про використання cookies, яке є обов'язковим згідно з законодавством про захист персональних даних. Також Google Analytics отримував дані без явної згоди користувача.

Виконано. Додано банер у нижній частині сторінки з кнопками «Прийняти» та «Скасувати». Дизайн банера відповідає кольоровій схемі сайту. Підтримуються українська та англійська мови. Вибір зберігається між сесіями. Інтегровано з Google Consent Mode v2 — аналітика не збирається до підтвердження згоди.

10. Блок запису на прийом — єдине джерело

Проблема. Блок «Залишити заявку» (CTA) з номером телефону та кнопкою запису вставлявся вручну на кожну сторінку окремо через Elementor. Будь-яка правка потребувала оновлення на кожній сторінці вручну. Крім того, текстові підписи в цьому блоці використовували теги заголовків (H6), хоча є просто підписами — це спотворювало ієрархію сторінки в сприйнятті Google.

Виконано.

  • Блок перетворено на єдиний шорткод [zdent_cta]: змінюєте один раз — оновлюється скрізь автоматично.
  • Теги H6 замінено на звичайні абзаци <p> — ієрархія заголовків більше не порушується.
  • Номер телефону став кнопкою-посиланням — на мобільних пристроях натискання одразу відкриває виклик.
  • Кнопка «Залишити заявку» тепер відкриває попап запису замість переходу на сторінку контактів.

Що залишилося зробити (разовий ручний крок): замінити старі вбудовані блоки CTA на всіх сторінках на HTML-віджет з кодом [zdent_cta]. Після цього управління блоком стає повністю централізованим.

11. Управління 301-редиректами

Запит клієнта. Можливість налаштовувати редиректи зі старих URL на нові через адмінку без участі розробника.

Заплановано. Буде встановлено плагін Redirection by John Godley через WP Admin → Plugins. Після встановлення редиректи можна керувати в WP Admin → Tools → Redirection — без правок у коді чи .htaccess.

12. Аварійне відновлення після оновлення WordPress 7

Що сталося. WordPress автоматично оновився до версії 7. Разом із цим автоматично оновилася тема Astra. У процесі оновлення конфігурація шапки сайту (розташування логотипу, меню, інших елементів) скинулася до стандартних значень — шапка і меню зникли з усіх сторінок.

Що зроблено.

  • Налаштування шапки відновлено з локальної бази даних без втрати жодного контенту.
  • Виявлено і виправлено 5 внутрішніх посилань, що вказували на тестову адресу розробника замість робочого сайту (логотип, посилання в меню).
  • В налаштуваннях сервера вимкнено автоматичне оновлення до нових мажорних версій WordPress — надалі оновлення 7.x → 8.x відбуватиметься тільки вручну після тестування.

Контент сайту (сторінки, статті, зображення, форми) не постраждав.

Що потрібно зробити після публікації

Від розробника (в WP Admin)

Технічні налаштування, що не можна змінити кодом:

  1. WP Structuring Markup → Local Business → «Address Country» → змінити на UA
  2. WP Structuring Markup → Local Business → «Output On» → прибрати галочку «Posts» (лишити лише «All Pages In Header»)
  3. WP Structuring Markup → відключити тип «Article»
  4. WP Structuring Markup → відключити тип «Site Navigation»
  5. WP Structuring Markup → Breadcrumb → «Home Name» → Головна
  6. WP Structuring Markup → Breadcrumb → увімкнути «Show Current Page»
  7. All in One SEO → Sitemaps → Таксономії → прибрати галочки «Категорії» та «Позначки»
  8. Elementor → Settings → Advanced → прибрати галочку «Lazy Load Background Images»
  9. Site Kit → Settings → увімкнути «Consent Mode»
  10. Settings → Privacy → переконатись, що сторінка «Політика конфіденційності» призначена в обох мовах (uk + en)
  11. Plugins → Add New → встановити Redirection by John Godley
  12. Code Snippets → знайти сніпет з попапом запису → змінити <h3 class="wc-popup-title"> на <p class="wc-popup-title">
  13. На кожній сторінці замінити старий блок CTA (Elementor) на HTML-віджет із кодом [zdent_cta]
  14. Elementor → Головна сторінка → 4 текстових блоки на темному фоні → HTML Tag → P

Від розробника (у формах CF7)

До кожної форми запису необхідно додати чекбокс згоди на обробку персональних даних (вимога GDPR):

  • У кожній українській формі перед [submit] додати: [acceptance gdpr_consent] Я погоджуюсь на обробку персональних даних відповідно до <a href="/polityka-konfidentsiynosti/">Політики конфіденційності</a>.[/acceptance]
  • У кожній англійській формі перед [submit] додати: [acceptance gdpr_consent] I agree to the processing of personal data in accordance with the <a href="/en/privacy-policy/">Privacy Policy</a>.[/acceptance]

Від клієнта (стосовно авторів статей)

Для коректного відображення авторів у Google необхідно:

  1. Створити окремі облікові записи для кожного лікаря, який публікує статті. Не публікувати від імені admin.
  2. У профілі кожного автора заповнити секцію «Schema.org»:
  • Person Name — повне ім'я (наприклад, «Векленко Тетяна Сергіївна»)
  • Instagram URL — посилання на профіль автора в Instagram
  1. Для всіх вже опублікованих статей змінити автора з admin на відповідного лікаря (відкрити статтю → панель «Автор» → вибрати → оновити).
